# My Custom Hyprland Dotfiles

*(config name: moodymoose)*

A from-scratch Hyprland setup on Arch Linux, written in Hyprland's Lua config
(0.55+) so the syntax is learned rather than copied. The design is modeled on
[LinuxBeginnings/Hyprland-Dots](https://github.com/LinuxBeginnings/Hyprland-Dots)
(the maintained, Lua-based successor of JaKooLit's Hyprland-Dots), but every
file here is built up piece by piece.

The core idea: **the wallpaper drives the theme.** One keypress picks a
wallpaper, and the window borders, rofi menus, kitty terminal, waybar,
notifications and lock screen all recolor to match it.

---

## What is in the box

| Piece | Tool | Notes |
|---|---|---|
| Compositor | Hyprland (Lua config) | split into small modules |
| Wallpaper | hyprpaper | block-style `hyprpaper.conf` |
| Color engine | wallust 3.x | extracts a palette from the wallpaper, fills templates |
| Menus | rofi 2.x | wallpaper picker, app launcher, power menu |
| Terminal | kitty | follows the wallpaper via kitty's own `kitten themes` |
| Bar | waybar 0.15 | pill-style modules, Nerd Font icons, power button |
| Notifications | dunst | colors from a wallust drop-in, do-not-disturb toggle |
| Lock screen | hyprlock | blurred current wallpaper, wallust colors |
| Idle | hypridle | lock after 5 min, screen off after 10; on/off toggle in waybar |
| Screenshots | grim + slurp + wl-clipboard | region, screen or window |
| Power profiles | power-profiles-daemon | waybar module and keybind; performance is labeled "Overclocking" |
| Qt / KDE apps | qt6ct | Dolphin and other Qt apps themed from the palette |
| Icons | generated "Wallust" icon theme | recolored Breeze Dark network and folder icons (tray icon, Dolphin) |

## Dependencies

From the official repos:

```bash
sudo pacman -S hyprland hyprpaper hyprlock hypridle rofi kitty dunst \
    network-manager-applet libnotify wireplumber brightnessctl playerctl \
    dolphin grim slurp wl-clipboard jq power-profiles-daemon qt6ct ttf-terminus-nerd
```

From the AUR:

```bash
yay -S wallust waybar-git   # wallust: the stable package, NOT wallust-git;
                            # waybar-git: needed for workspace clicks (see Notes)
```

Notes:

- **rofi 2.0 or newer** is required. Wayland support was merged into the main
  `rofi` package in 2.0.0, so the old `rofi-wayland` package is not needed.
- **wallust 3.x.** The wallust 4 line is a pre-release with an incompatible
  config format (`wallust migrate` converts it). The config here is for v3.
- `power-profiles-daemon` is a service: enable it with
  `sudo systemctl enable --now power-profiles-daemon`, and do not run another
  power manager (tlp, auto-cpufreq) next to it.
- **waybar needs a build newer than 0.15.0 (`waybar-git`).** The 0.15.0 release
  sends old-style dispatch strings that Hyprland's Lua config rejects, so clicking
  the workspace numbers does nothing. Test: `hyprctl dispatch workspace 3` fails,
  `hyprctl dispatch 'hl.dsp.focus({ workspace = 3 })'` works. Switch back to the
  `waybar` package once a release includes the fix.
- `breeze-icons` (a dependency of Dolphin) provides the `breeze-dark` icon theme
  the Wallust icon theme is built from; `perl` (part of `base`) does the recoloring.
- `wpctl` (volume keys) comes from `wireplumber`; `notify-send` from `libnotify`;
  `jq` is only used by the focused-window screenshot mode.
- **Fonts:** Terminess Nerd Font (`ttf-terminus-nerd`) is the font everywhere.
  `Symbols Nerd Font Mono` is used by waybar as a glyph fallback.

## How it fits together

Pressing **`SUPER + W`** runs `moodymoose-scripts/wallpaper-select.sh`, which only
picks and applies the image:

1. A rofi grid of thumbnails from `~/Pictures/wallpapers` (theme: `wallpaper.rasi`).
2. The choice is written into `hyprpaper.conf`, so it survives a re-login, and
   applied immediately with `hyprctl hyprpaper wallpaper ",<path>,cover"`.
3. It hands off to `theme-refresh.sh` with the image path.

`theme-refresh.sh [image]` does everything else. It can also be run on its own;
with no argument it uses the current wallpaper (from `hyprpaper.conf`, then the
`wallpaper-current` symlink, then the first image in the wallpapers folder):

1. It creates the folders that only hold generated files and points
   `~/.cache/wallpaper-current` at the image (hyprlock reads that link).
2. It checks whether kitty is currently on the wallust theme (by looking for the
   `## name: Wallust` marker in `current-theme.conf`). This has to happen before
   wallust rewrites the theme file.
3. `wallust run` extracts a palette from the image and renders every template:
   Hyprland (`colors.lua`), rofi (`wallust-colors.rasi`), kitty
   (`themes/Wallust.conf`), waybar (`colors.css`), dunst (`50-wallust.conf`),
   hyprlock (`hyprlock-colors.conf`) and the Qt color scheme
   (`qt6ct/colors/Wallust.conf`), plus a shell-readable copy of the palette
   (`~/.cache/wallust-colors.env`). If wallust fails, the script stops and
   notifies you, leaving the running apps on their old colors.
4. wallust only prints a warning when a template file is missing, so the script
   checks that every generated file exists and sends a critical notification
   naming any that do not.
5. It reloads what uses the palette: kitty (only if it was on the wallust theme,
   with `kitten themes --reload-in=all Wallust`), dunst (`dunstctl reload`),
   the tray icon theme (`icon-theme-refresh.sh`), waybar (restarted so it reads
   the new `colors.css` and icons) and finally Hyprland (`hyprctl reload`, which
   updates the window borders).

`theme-refresh.sh --if-missing` runs the full refresh only when a generated file
is missing, and exits immediately otherwise. It is the first entry in the
autostart list, so a fresh clone repairs itself at login.

Hyprlock reads its config and colors each time it starts, so it needs no reload
step.

### Colors in the Hyprland config

`palette.lua` loads the generated `colors.lua` inside `pcall`, so a missing or
broken file falls back to defaults (the original cyan-to-green look) and never
stops the config from loading. `decoration.lua` then uses it:

- active border: a 45-degree gradient from `color12` to `color13`
- inactive border: `color0`

### wallust configuration

`~/.config/wallust/wallust.toml`:

```toml
backend     = "fastresize"
color_space = "labmixed"
palette     = "dark16"
threshold   = 11

[templates]
hypr.template         = 'colors-hyprland.lua'
hypr.target           = '~/.config/hypr/moodymoose-configs/colors.lua'
rofi.template         = 'colors-rofi.rasi'
rofi.target           = '~/.config/rofi/wallust-colors.rasi'
kitty.template        = 'colors-kitty.conf'
kitty.target          = '~/.config/kitty/themes/Wallust.conf'
waybar.template       = 'colors-waybar.css'
waybar.target         = '~/.config/waybar/colors.css'
dunst.template        = 'colors-dunst.conf'
dunst.target          = '~/.config/dunst/dunstrc.d/50-wallust.conf'
hyprlock.template     = 'colors-hyprlock.conf'
hyprlock.target       = '~/.config/hypr/hyprlock-colors.conf'
qt.template           = 'colors-qt.conf'
qt.target             = '~/.config/qt6ct/colors/Wallust.conf'
shell.template        = 'colors-shell.env'
shell.target          = '~/.cache/wallust-colors.env'
```

The kitty template starts with a `## name: Wallust` line. `kitten themes` lists
the file as the theme "Wallust", and the scripts use that marker to tell
whether kitty is currently on the wallpaper theme.

Run wallust by hand (for example after a fresh install) with:

```bash
wallust run -s --templates-dir ~/.config/wallust/templates ~/Pictures/wallpapers/<image>
```

## Components in detail

### Hyprland config modules

`hyprland.lua` loads, in order: `monitors`, `env`, `decoration`, `settings`,
`rules`, `keybinds`, `autostart`. `programs` and `palette` are not listed
because they only return tables and load the first time another file
`require`s them.

Current look: `gaps_in 5`, `gaps_out 15`, `border_size 3`, rounding 10, blur
and shadow on, dwindle layout.

`programs.lua` holds the default programs (kitty, dolphin, and the rofi
launcher command) in one place:

```lua
return {
  terminal    = "kitty",
  fileManager = "dolphin",
  menu        = "pkill rofi || rofi -show drun -theme $HOME/.config/rofi/launcher.rasi",
}
```

### Autostart

`theme-refresh.sh --if-missing` (repairs missing generated files), then
`nm-applet`, `waybar`, `hyprpaper`, `dunst` and `hypridle`, started from
`hl.on("hyprland.start", ...)` so they run once per session and not on every
config reload.

### Kitty

`kitty.conf` includes `current-theme.conf`, the file kitty's own theme tool
writes. Themes are chosen with kitty's built-in selector, `kitten themes`:

- **`SUPER + CTRL + K`** opens it in a floating kitty window (class
  `kitty-themes`, floated by a rule in `rules.lua`) with
  `--reload-in=all`, so every open kitty window changes, not just the selector.
  Type to search, use the arrow keys to preview, and apply a theme from the
  prompt. The first launch downloads kitty's theme collection, so it needs
  internet access.
- **The wallpaper theme** is a user theme: wallust writes
  `~/.config/kitty/themes/Wallust.conf`, and the selector lists it as "Wallust".
  `SUPER + SHIFT + W` applies it directly with
  `kitten themes --reload-in=all Wallust`.

Changing the wallpaper only touches kitty when it is already on the Wallust
theme (`theme-refresh.sh` looks for the `## name: Wallust` marker in
`current-theme.conf` before wallust rewrites the file), so a theme chosen on
purpose is never overridden.

### Icons (the generated Wallust icon theme)

Waybar's tray draws each icon as a finished picture that the applet asks GTK for
by name; CSS `color` cannot recolor it (it is loaded as a bitmap), so the network
icon used to be black on the dark bar. Icon themes in general do not follow the
palette either, and fixed-color artwork such as Oxygen never will. Breeze icons are
SVGs with named color slots, so `icon-theme-refresh.sh` builds a small icon theme
called **Wallust** in `~/.local/share/icons/Wallust/`:

- It inherits everything from `breeze-dark` (`Inherits=breeze-dark` in its
  generated `index.theme`) and overrides only a few categories, for every numeric
  size Breeze Dark ships: the `nm-*` and `network-*` status icons (the tray icon),
  the `folder*` and `user-*` places icons (folders, home, desktop, trash) and
  `inode-directory*` from mimetypes (the name Dolphin asks for). Each category is
  one `copy_set` line in the script; `cp -L` follows Breeze's symlinks so every
  file is a real SVG.
- Recoloring rewrites the `.ColorScheme-*` classes in each SVG's embedded
  stylesheet: text becomes the foreground, highlight and accent the accent color
  (`color12`), neutral `color13`, positive `color10` and negative the warning color
  (`color9`). Large folders use the accent slot; the small 16 and 22 px folders
  are outlines in the text color. The palette comes from
  `~/.cache/wallust-colors.env`, a shell-sourceable file wallust generates.
- `theme-refresh.sh` runs the builder just before restarting waybar.

The theme is selected in three places:

- **GTK** (the tray): `gtk-icon-theme-name=Wallust` in
  `~/.config/gtk-3.0/settings.ini` and
  `gsettings set org.gnome.desktop.interface icon-theme 'Wallust'`.
- **KDE**: `kwriteconfig6 --file kdeglobals --group Icons --key Theme Wallust`.
  This one matters: KDE's GTK sync copies KDE's icon setting into `settings.ini` and
  gsettings at login, so with `kdeglobals` still on `breeze` the tray icon turned
  black again after every reboot.
- **Qt** (Dolphin): `icon_theme=Wallust` in `~/.config/qt6ct/qt6ct.conf` (tracked in
  the repo).

Limits: only icons an app requests by name from the theme can be recolored (apps
that embed their own pictures cannot). File-type and app icons are inherited from
Breeze Dark, not recolored, because many are multi-color. Dolphin loads icons at
startup, so reopen it after a wallpaper change; if it still shows old colors, delete
KDE's cache (`rm -f ~/.cache/icon-cache.kcache`) and restart it.

### Qt apps (Dolphin)

`env.lua` sets `QT_QPA_PLATFORMTHEME=qt6ct` and `QT_STYLE_OVERRIDE=Fusion`, so Qt
programs started from Hyprland take their palette from qt6ct and use the Fusion
widget style. Environment variables only reach programs started after they are
set, so restart a Qt app after changing them. wallust writes the palette as a
qt6ct color scheme (`~/.config/qt6ct/colors/Wallust.conf`: three lines of 21
colors in Qt's palette-role order, for the active, disabled and inactive
states). `qt6ct.conf` (created once with the `qt6ct` tool) selects the style, the
custom palette, the icon theme and the fonts; it stores the scheme path as an
absolute path, so re-select the scheme in qt6ct on a new machine.

KDE apps such as Dolphin take their colors from `~/.config/kdeglobals`, not the
Qt palette, and fall back to a light default when nothing is set there. This
one setting makes them use the qt6ct palette (the name `qt6ct` is not a real KDE
scheme, so they fall back to the platform palette):

```bash
kwriteconfig6 --file kdeglobals --group UiSettings --key ColorScheme qt6ct
```

`kdeglobals` is shared with a Plasma session if you also log into one, and Plasma
overwrites this key when you change colors in System Settings. It is not part of
the Dotfiles repo, so repeat the command on a fresh machine. Dolphin can also
override the color scheme itself (`ColorScheme` in `~/.config/dolphinrc`).

### Rofi

Three themes, all importing `wallust-colors.rasi`: `wallpaper.rasi` (thumbnail
grid), `launcher.rasi` (list of apps with icons) and `power.rasi` (the power
menu). The menus show the colors from the
previous wallpaper pick, because wallust runs after the choice is made.

### Waybar

Left: workspaces 1 to 5 (always shown) and the focused window title. Center:
clock. Right: volume, network, power profile, CPU, memory, tray, an auto-lock padlock, a
do-not-disturb bell and a power button. Every
module is a rounded pill with an accent border, colored from `colors.css`.
Icons are Nerd Font glyphs written as `\uXXXX` escapes in `config.jsonc`, with
the font stack `"Terminess Nerd Font", "Symbols Nerd Font Mono", monospace`.
The power button (`custom/power`) opens the power menu. The bell
(`custom/dnd`) shows whether notifications are on or paused and toggles them
on click. The padlock (`custom/autolock`) shows whether auto-lock is on (closed)
or off (open, in the warning color) and toggles it on click.

The workspace buttons are clickable (this needs `waybar-git`, see Dependencies).
The tray holds `nm-applet`'s icon (click it for network settings); the network
module itself (IP address and interface) is display-only.

### Dunst

`dunstrc` sets the layout (top-right, below the bar, 3px frame and rounded
corners to match the windows, Terminess Nerd Font). Colors come from the
wallust drop-in `dunstrc.d/50-wallust.conf`: accent frame for normal
notifications, a muted frame for low urgency and the warning color for
critical ones. Dunst reads a drop-in only if a base `dunstrc` exists next to
it, which is why the base file is required.

### Power profiles

Waybar's built-in `power-profiles-daemon` module shows the active profile and
cycles through the available ones when clicked. Each entry in its `format-icons`
is an icon plus a text label, which is how the `performance` profile reads
**Overclocking** (a label only: on this machine `powerprofilesctl list` shows a
single driver, `intel_pstate`, which changes the CPU's energy/performance
preference, and the platform driver is a placeholder). The module carries a CSS
class named after the active profile, so `performance` uses the warning color and
`power-saver` the secondary accent.

`power-profile.sh` cycles the profile from the keyboard (`SUPER + SHIFT + P`): it
reads the available profiles from `powerprofilesctl list`, moves to the next one
(wrapping around), and sends a short notification. Waybar updates by itself,
because the module listens to the daemon.

### Do not disturb

`dnd.sh toggle` runs `dunstctl set-paused toggle`: while paused, dunst keeps
notifications but does not show them until it is unpaused. The script then
sends waybar the real-time signal `SIGRTMIN+8`, which makes the `custom/dnd`
module re-run `dnd.sh status` and redraw (a bell when notifications are on, a
crossed-out bell in the warning color when paused). Turning notifications back
on shows a short "Notifications on" message, and anything held while paused
appears after it. `SUPER + N` or a click on the bell toggles it. An optional
dunst rule (`msg_urgency = critical` with `override_pause_level = 100`) can let
critical notifications through while paused.

### Auto-lock toggle

`autolock.sh toggle` stops `hypridle` if it is running and starts it
(`setsid hypridle`) if it is not, then signals waybar with `SIGRTMIN+9` so the
`custom/autolock` module re-runs `autolock.sh status`. The state is simply
"does a process named `hypridle` exist" (`pgrep -x hypridle`), so there is no
state file to get out of sync. Stopping hypridle disables both the idle lock and
the idle screen-off; `SUPER + L` still locks manually. `SUPER + SHIFT + L` or a
click on the padlock toggles it.

Waybar's built-in `idle_inhibitor` module was not used because its state lives
inside waybar, which `theme-refresh.sh` restarts on every wallpaper change, so
auto-lock would silently switch back on after each pick. Because hypridle is
started from autostart, auto-lock is on again after every login.

Suspend from the power menu does not depend on hypridle: it locks the screen
itself before sleeping, so waking never shows an unlocked desktop even with
auto-lock off.

### Hyprlock and hypridle

`hyprlock.conf` sources `hyprlock-colors.conf` and shows the blurred current
wallpaper (via `~/.cache/wallpaper-current`), a clock, the date, the username
and a password box that uses the accent color. `SUPER + L` runs it
(`pidof hyprlock || hyprlock`).

`hypridle.conf` locks the session after 5 minutes (`loginctl lock-session`,
which triggers `lock_cmd`) and turns the screen off after 10. The screen-off
command is `hyprctl dispatch hl.dsp.dpms '{ action = "off" }'`. There is no
suspend timer.

### Screenshots

`screenshot.sh [region|screen|window]` captures with `grim` (using `slurp` for
the region selector, or `hyprctl activewindow -j` plus `jq` for the focused
window), saves a timestamped PNG in `~/Pictures/Screenshots`, copies it to the
clipboard with `wl-copy` and sends a dunst notification.

### Power menu

`power-menu.sh` shows Lock, Logout, Suspend, Reboot and Shutdown in rofi.
Logout, Reboot and Shutdown ask for confirmation first, with "No, cancel" as
the first and default entry. It is opened by `SUPER + Escape` or the waybar
power button.

Suspend first starts hyprlock (if it is not already running), waits for it to
come up and pauses a second, then runs `systemctl suspend`, so the session is
locked before the machine sleeps whether or not hypridle is running (hypridle's
own `before_sleep_cmd` also locks, and the `pidof hyprlock ||` guard prevents a
second lock screen). To test without sleeping, run
`SUSPEND_CMD="echo would suspend" power-menu.sh`: it locks, then prints instead
of suspending.

## Version control

The config lives in a Dotfiles repo with one folder per app. Each folder in
`~/.config` is a symlink into it:

```
~/.config/hypr    -> ~/Projects/Dotfiles/hyprland
~/.config/kitty   -> ~/Projects/Dotfiles/kitty
~/.config/wallust -> ~/Projects/Dotfiles/wallust
~/.config/rofi    -> ~/Projects/Dotfiles/rofi
~/.config/waybar  -> ~/Projects/Dotfiles/waybar
~/.config/dunst   -> ~/Projects/Dotfiles/dunst
~/.config/qt6ct   -> ~/Projects/Dotfiles/qt6ct
```

Edit files at their `~/.config/...` paths as usual; the links pass straight
through to the repo.

Wallust overwrites several files on every wallpaper pick, and a few others are
machine state, so they are not committed. The repo's `.gitignore`:

```gitignore
# --- generated by wallust (rewritten on every wallpaper pick) ---
**/moodymoose-configs/colors.lua
**/rofi/wallust-colors.rasi
**/waybar/colors.css
**/kitty/themes/Wallust.conf
**/dunst/dunstrc.d/50-wallust.conf

# --- machine state, not configuration ---
# rewritten by wallpaper-select.sh, contains an absolute path
**/hyprland/hyprpaper.conf
```

An ignore rule does not affect files git already tracks. If a generated file
was committed earlier, stop tracking it with `git rm --cached <file>` (the
`--cached` keeps the file on disk). Check that a path is ignored with
`git check-ignore -v <path>`.

## First run after cloning

On a fresh machine the ignored files do not exist, and some programs import
them (the rofi themes import `wallust-colors.rasi`, waybar imports `colors.css`,
hyprlock sources `hyprlock-colors.conf`). `theme-refresh.sh` creates them, and
the folders that only ever hold generated files, so setup is short:

```bash
# 1. link the config folders into place
for pair in hypr:hyprland kitty:kitty wallust:wallust rofi:rofi waybar:waybar dunst:dunst qt6ct:qt6ct; do
    ln -s "$HOME/Projects/Dotfiles/${pair#*:}" "$HOME/.config/${pair%%:*}"
done

# 2. create the image folders and put at least one image in the first one
mkdir -p ~/Pictures/wallpapers ~/Pictures/Screenshots

# 3. generate every palette and reload (uses the first image it finds)
~/.config/hypr/moodymoose-scripts/theme-refresh.sh

# 4. activate the kitty wallust theme (also creates current-theme.conf)
kitten themes --reload-in=all Wallust

# 5. press SUPER + W and pick a wallpaper (this also creates hyprpaper.conf)

# 6. Qt apps (Dolphin): run qt6ct once (Style: Fusion, Palette: Custom, scheme:
#    Wallust, pick an icon theme), then make KDE apps use that palette
kwriteconfig6 --file kdeglobals --group UiSettings --key ColorScheme qt6ct

# 7. Icons (nm-applet tray icon, Dolphin folders): point GTK and KDE at the generated
#    icon theme (create ~/.config/gtk-3.0/settings.ini with a [Settings] section if it
#    is missing; qt6ct.conf in the repo already has icon_theme=Wallust)
sed -i 's/^gtk-icon-theme-name=.*/gtk-icon-theme-name=Wallust/' ~/.config/gtk-3.0/settings.ini
gsettings set org.gnome.desktop.interface icon-theme 'Wallust'
kwriteconfig6 --file kdeglobals --group Icons --key Theme Wallust
```

Hyprland itself does not need step 3 to start: `palette.lua` falls back to
default colors if `colors.lua` is missing. Do step 3 before relying on the lock
screen, which sources `hyprlock-colors.conf`. After the first login,
`theme-refresh.sh --if-missing` in autostart keeps those files in place.

## Customizing

- **Autostart something:** add the command to the `startup` list in `autostart.lua`.
- **Change a default program:** edit `programs.lua`.
- **Add wallpapers:** drop images into `~/Pictures/wallpapers`.
- **Change which palette colors the borders use:** edit the `col` block in
  `decoration.lua` (any of `color0` to `color15`, `background`, `foreground`).
- **Change idle timings:** edit the two `timeout` values in `hypridle.conf` and
  restart it with `pkill -x hypridle; setsid hypridle >/dev/null 2>&1 &`.
- **Theme another app:** add a template to `~/.config/wallust/templates`, add a
  `name.template` / `name.target` pair to `wallust.toml`, make sure the target's
  folder exists, import the generated file from the app's config, add the file
  to `.gitignore`, and add its output file to the `generated` list and a reload line in
  `theme-refresh.sh`.

## Lessons learned (things that bit during the build)

- **A `local` is only visible inside its own file.** Shared values live in
  `programs.lua` and are `require`d.
- **A bare `hl.exec_cmd` at the top level of a config file runs again on every
  reload.** Startup commands belong inside `hl.on("hyprland.start", ...)`.
- **`hl.exec_cmd` strings are glob-expanded by Hyprland.** Use `test -e file`
  instead of `[ -e file ]` inside those strings.
- **`pkill -USR1 kitty` also matches any script with "kitty" in its name,** so
  the script kills itself. Use `pkill -x kitty` for an exact name match.
- **wallust v3 and v4 configs are not compatible.** Install the AUR package
  `wallust`, not `wallust-git`.
- **wallust only warns when a template file is missing** (and carries on), so
  `theme-refresh.sh` verifies the outputs itself. A template once went missing
  because vim had left only a `colors-hyprlock.conf~` backup copy; check
  file names with `ls` after creating a file.
- **Waybar did not reliably pick up an `@import`ed stylesheet on `SIGUSR2`.**
  The script restarts it instead.
- **The kitty marker (`## name: Wallust`) is what the script checks,** not file
  equality, so switching away and back never breaks the link.
- **Verify the file on disk, not the one you meant to save.** Stale copies of
  `wallpaper-select.sh` were missing the waybar, reload and wallpaper-symlink
  lines more than once. `grep` the script for the line you expect.
- **`config.jsonc` is strict JSON apart from comments.** A trailing comma stops
  waybar from starting; the error names the line.
- **`notify-send` waits about 25 seconds when no notification daemon answers.**
  Scripts that notify do it last, in the background and under `timeout`, so a
  stopped dunst can never stall the real work or the waybar icon refresh.
- **Waybar's `idle_inhibitor` state dies with waybar,** and the wallpaper
  pipeline restarts waybar, so auto-lock is tracked by whether `hypridle` is
  running instead.
- **KDE apps (Dolphin) ignore the qt6ct palette unless `kdeglobals` points at it.**
  They read their colors from `~/.config/kdeglobals`; `[UiSettings]
  ColorScheme=qt6ct` makes them use the qt6ct palette. Icons and fonts from
  qt6ct apply either way, which makes the problem look like a half-working theme.
- **The waybar 0.15.0 release breaks workspace clicks under the Lua config.** It
  sends legacy dispatch strings; `waybar-git` has the fix.
- **KDE's GTK sync resets the GTK icon theme at login.** `kded6` copies KDE's
  icon setting into `settings.ini` and gsettings, so changing only the GTK side
  lasts until the next boot. Set `[Icons] Theme` in `kdeglobals` as well.
- **Fixed-color icon themes (Oxygen) cannot follow the palette.** Breeze icons
  can, because their colors are named slots in the SVG.
- **Tray icons cannot be recolored with CSS.** They are bitmaps looked up by
  name in the GTK icon theme, so a dark theme (`breeze`) gives a black icon on
  a dark bar. The fix is an icon theme that carries palette-colored copies.
- **Lock first, and wait for the lock, before suspending.** Starting hyprlock and
  suspending in the same instant can put the machine to sleep before the session
  lock engages. The power menu waits for hyprlock to be running and pauses a
  second before suspending.
- **Hyprland `env` values only reach programs started afterwards.** Open a new
  terminal (or restart the app) after changing `env.lua`.
- **Hyprlock needs its config to exist, and a wrong password three times in a
  row locks you out for 10 minutes on Arch** (`pam_faillock`). Test unlocking
  with the right password first, and keep a TTY handy: `pkill -USR1 hyprlock`
  from another console unlocks the session.
- **Dunst only reads drop-ins next to the `dunstrc` it loaded,** so the base
  file must exist.
- **Git does not track empty directories,** so folders holding only generated
  files must be recreated on a fresh clone.
- **An ignore rule does not untrack a file git already has.** Use
  `git rm --cached`.
- `ls` is aliased to `lsd` on this machine, which rejects GNU flags such as
  `--time-style`; use `stat` or `command ls`.

## Troubleshooting

| Symptom | Check |
|---|---|
| A generated file is missing, or wallust prints `[W] ... failed: No such file` | run `theme-refresh.sh`; check `ls ~/.config/wallust/templates/` for a missing or misnamed template (for example a trailing `~`) |
| Borders do not change after a wallpaper pick | `hyprctl reload` runs last in the script; `moodymoose-configs/colors.lua` should have a fresh timestamp |
| Waybar keeps old colors | `~/.config/waybar/colors.css` timestamp; the script should restart waybar |
| Waybar will not start | run `waybar` in a terminal; JSON errors name the line (often a trailing comma) |
| Kitty does not follow the wallpaper | `head -2 ~/.config/kitty/current-theme.conf` should start with `## name: Wallust`; if it is on another theme, that is by design |
| Rofi menu has no colors or errors | `~/.config/rofi/wallust-colors.rasi` must exist; run wallust once by hand |
| Notifications keep old colors | `dunstctl reload`; check `~/.config/dunst/dunstrc.d/50-wallust.conf` exists |
| Workspace numbers in waybar do not respond to clicks | `waybar --version` must be a build with the Lua dispatch fix (`waybar-git`); compare `hyprctl dispatch workspace 3` with `hyprctl dispatch 'hl.dsp.focus({ workspace = 3 })'` |
| Tray icon is black or does not follow the wallpaper | `grep icon-theme ~/.config/gtk-3.0/settings.ini` and `gsettings get org.gnome.desktop.interface icon-theme` must say `Wallust` (if they flip back to `breeze` after a reboot, set `[Icons] Theme=Wallust` in `kdeglobals`); run `icon-theme-refresh.sh`; compare the color in `~/.local/share/icons/Wallust/status/22/nm-device-wired.svg` with `~/.cache/wallust-colors.env` |
| Dolphin folders are not in the palette colors | `icon_theme=Wallust` in `~/.config/qt6ct/qt6ct.conf` and `[Icons] Theme=Wallust` in `kdeglobals`; run `icon-theme-refresh.sh`; check `~/.local/share/icons/Wallust/places` exists; fully restart Dolphin; delete `~/.cache/icon-cache.kcache` if it still shows old colors |
| Dolphin (or another KDE app) is still white | `kdeglobals` needs `[UiSettings] ColorScheme=qt6ct`; check `~/.config/dolphinrc` has no `ColorScheme` override, then fully restart Dolphin (`pkill -x dolphin`); env vars only apply to programs started after `hyprctl reload` |
| Power profile pill missing or empty | `systemctl status power-profiles-daemon` must be active; `powerprofilesctl list` shows the profiles the hardware offers |
| Auto-lock padlock does not change when clicked | run `autolock.sh toggle` by hand and check `pgrep -x hypridle`; the module listens on signal 9: `pkill -SIGRTMIN+9 -x waybar` |
| `notify-send` hangs or prints "Timeout was reached" | dunst is not running: `pgrep -a dunst`; start it with `setsid dunst >/dev/null 2>&1 &` |
| Do-not-disturb icon does not change | the module listens on signal 8: `pkill -SIGRTMIN+8 -x waybar`; `dunstctl is-paused` shows the real state |
| Lock screen shows an old wallpaper | `readlink ~/.cache/wallpaper-current` should match the active wallpaper |
| Screen never turns off or back on | test `hyprctl dispatch hl.dsp.dpms '{ action = "off" }'` by hand, then `on` |
| Screenshot key does nothing | run `screenshot.sh screen` by hand to see its error; check `wev` for the key name |
| Wallust prints a template error | run it by hand and read the message; check `wallust --version` is 3.x |
| Wallpaper does not change | `hyprctl hyprpaper --help`; hyprpaper must be running and use the block-style config |
| Config error banner after editing | the banner names the file; the config is modular, so bisect by commenting out one `require` at a time |
